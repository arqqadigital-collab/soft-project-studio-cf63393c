| Hreflang | ✅ | `en`/`ar`/`x-default` alternates computed from `routeMap.findCounterpart()` in SeoHead.tsx, and also included per-URL in the sitemap. This is a genuinely solid implementation. |
| JSON-LD Schema | 🟡 | Per-entity-type schema exists: `Article` (posts, case studies), `Event` (events) — hardcoded in [ArticleDetail.tsx](src/pages/ArticleDetail.tsx:181), [EventDetail.tsx](src/pages/EventDetail.tsx:179), [CaseStudyDetail.tsx](src/pages/CaseStudyDetail.tsx:172). An admin can override with fully custom JSON-LD via the `schema_markup` field in SeoEditor. **CMS pages ([PublicPage.tsx](src/pages/PublicPage.tsx:153)) and all 30+ coded marketing pages (Dental.tsx, HIS.tsx, etc.) emit no schema at all unless manually pasted.** |
| Breadcrumb Schema | ❌ | No `BreadcrumbList` JSON-LD anywhere. (There's a `breadcrumb.tsx` UI component for visual breadcrumbs only — unrelated to structured data.) |
| Organization Schema | ❌ | No sitewide `Organization` JSON-LD anywhere (not in `index.html`, not in any root component). |
| Website Schema | ❌ | No `WebSite` JSON-LD (which also normally carries the sitelinks searchbox markup). |
| Article Schema | ✅ | See JSON-LD row above — solid for posts/case-studies. |
| FAQ Schema | ❌ | The page builder has a real "FAQ" section type ([pageSections.tsx:701](src/lib/pageSections.tsx:701)) used on many marketing pages, but it is **purely visual** — no automatic `FAQPage` JSON-LD is generated from its Q&A items. Only achievable today by an admin hand-writing the schema JSON into `schema_markup`. |
| Local Business Schema | ❌ | No `LocalBusiness`/`Organization` markup, no NAP (name/address/phone) fields anywhere in `site_settings` or the dashboard. |

## 2. Redirects

| Feature | Status | Notes |
|---|---|---|
| Redirect Manager | ✅ | Dashboard UI in [SeoDashboard.tsx](src/pages/dashboard/SeoDashboard.tsx) (Redirects tab) backed by `slug_redirects` table. Also auto-populated by a DB trigger (`capture_slug_change()`) whenever a post/page slug changes — a nice touch that prevents self-inflicted 404s. |
| Real HTTP 301 | ✅ | As of the just-shipped SEO infra work, Apache serves real `301` via `.htaccess`'s AUTO SEO block, generated by `seo-sync.php` from `slug_redirects` (through the `seo-routes` Edge Function). |
| 302 (temporary redirects) | ❌ | `slug_redirects` has no `redirect_type`/status-code column; every redirect is hardcoded to 301 in both `PathRedirect.tsx` (client-side) and `seo-sync.php` (`[R=301,L]`). No way to do a temporary redirect. |
| Bulk Redirects | ❌ | Add/remove is one-at-a-time via two text inputs; no CSV/bulk paste, no multi-row form. |
| Import / Export | ❌ | No CSV import, no export button anywhere in the Redirects tab. |
| Redirect Logs | ❌ | No hit-count, no last-triggered timestamp, no table logging which redirects actually fire on Apache or client-side. You can see *what redirects exist*, not *whether/how often they're used*. |

## 6. Social Media (global links)

🟡 **Partially implemented, but functionally works for all 8 requested platforms.**

Global social links exist as a free-form, dashboard-editable list: `site_settings`/`headerFooter` → `footer_social: { platform: string; url: string }[]`, edited in [HeaderFooterEditor.tsx](src/pages/dashboard/HeaderFooterEditor.tsx:732) and rendered in [Footer.tsx](src/components/Footer.tsx:81). An admin can add Facebook, Instagram, LinkedIn, X, YouTube, TikTok, WhatsApp (`wa.me/...`), Telegram (`t.me/...`), or literally anything else, by typing a label and a URL.

**Limitations:**
- No icon system — `{s.platform}` is rendered as plain text (e.g. the word "Facebook"), not a recognizable brand icon. This looks unfinished on the live site.
- No platform-specific validation (e.g. nothing stops a malformed `wa.me` link or catches a non-URL).
- No dedicated "Social Links" settings screen — it's buried inside the general Header/Footer editor, which isn't where an SEO/marketing person would intuitively look for it.

## 7. Analytics

| Feature | Status | Notes |
|---|---|---|
| Google Analytics 4 | ❌ | No `gtag.js`, no measurement ID field, nothing in `index.html` or any component. |
| Google Tag Manager | ❌ | No GTM container snippet or ID field anywhere. |
| Google Search Console Verification | ❌ | No verification meta tag or file-based mechanism (`google-site-verification` doesn't appear anywhere in the repo). |
| Microsoft Clarity | ❌ | Not present. |
| Meta Pixel | ❌ | Not present. |

**However — there is a real, custom-built first-party analytics system that isn't in your checklist but is worth flagging:**
- `page_views` table + `log-view` Edge Function ([supabase/functions/log-view/index.ts](supabase/functions/log-view/index.ts)) + [src/lib/analytics.ts](src/lib/analytics.ts): logs a privacy-respecting page view (IP+UA hashed, not stored raw) per post/page, with bot filtering, per-IP rate limiting, and per-day dedupe.
- 🟡 Partial: `logPageView()` is only called from `ArticleDetail.tsx` (blog posts) and `PublicPage.tsx` (CMS pages) — **events, case studies, and all ~30 coded marketing pages (Dental, HIS, Dynamics365, etc.) are never tracked.**
- 🟡 Partial: the only place this data surfaces in the Dashboard is a single raw "Views" count on `DashboardHome.tsx` — no per-page breakdown, no trend chart, no top-pages/top-referrers report, despite the underlying data (`referrer`, `viewed_day`) supporting it.

This means: **zero third-party analytics integration**, but a legitimate (if underused) internal analytics foundation already exists and would be relatively cheap to extend rather than needing to be built from scratch.

## Summary

### 1. Existing features (already production-ready)
- Per-entity meta title/description with EN/AR translations
- Hreflang (en/ar/x-default) — solid, mirrors the client-side route map exactly
- Open Graph + Twitter Card meta tags
- Article/Event JSON-LD for posts, case studies, events
- Robots.txt + Sitemap.xml — dashboard-editable, dynamically generated, auto-synced to Apache
- Redirect Manager with real HTTP 301s (client-side + now Apache-level), auto-capture on slug change
- Real HTTP 404 (Apache-level, matching custom Not Found page)
- Google/Social preview cards in the SEO editor
- Global social links list (functional, if visually unfinished)
- Internal first-party page-view logging (privacy-respecting, bot-filtered)

### 2. Features that only need small improvements
- Twitter `site`/`creator` handle field — one field + one meta tag
- Canonical URL validation/auto-suggestion for paginated list pages
- Social link icons in the Footer (map `platform` string → a lucide icon)
- Extend `logPageView()` calls to events/case-studies/coded pages (the pipe already exists)
- A basic "Views over time" / "Top pages" chart on top of existing `page_views` data
- Sitemap ping to Google/Bing after `seo-sync.php` runs (one more `fetch()` call)

### 3. Missing features — HIGH PRIORITY
- Google Search Console verification tag + GA4 (or at least *a* third-party analytics) — right now there is **no way to see real traffic, keyword, or search-performance data** at all
- Organization + WebSite JSON-LD (sitewide, cheap to add, meaningfully improves rich-result eligibility and brand knowledge panel odds)
- FAQPage JSON-LD auto-generated from the existing FAQ page-builder section (the content already exists, it's just not marked up)
- Image optimization (srcset/responsive images, or at minimum compressing the several 1–5MB assets) and JS code-splitting — both are directly hurting Core Web Vitals, which is itself an SEO ranking factor
- 404 monitoring / broken-link visibility (you're flying blind on what's currently 404ing for real visitors)

### 4. Missing features — LOW PRIORITY
- 302 support, bulk redirect import/export, redirect hit logs
- UTM builder, campaign manager, conversion/event tracking, Meta Pixel, Microsoft Clarity, GTM
- Local Business / Breadcrumb schema (only matters if you have a physical storefront / want breadcrumb rich results)
- Facebook App ID
- Bulk alt-text auditing tool
